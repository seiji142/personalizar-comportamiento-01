Los Fixes (3 Cambios)

Fix 1: Actualizar CLI a 1.18.31

El API de OpenCode Zen rechaza clientes menores a 1.17.0 con error 426 (Upgrade Required). La desktop app no actualizaba el CLI automáticamente.

# ANTES (broken) opencode --version 1.15.11 # DESPUÉS (funciona) npm install -g opencode-ai opencode.cmd --version 1.18.31

Por qué: El API tiene un mínimo de versión para el free tier. Actualizar el CLI es obligatorio.

Fix 2: tests/lib/opencode_cli.py (módulo compartido)

Creado un módulo que busca el CLI en múltiples ubicaciones. Todos los scripts importan de aquí.

Por qué: npm instala en AppData\Roaming, la desktop app en AppData\Local. Buscar en ambas ubicaciones.

Fix 3: tests/example/test_minimal.py (debug del ciclo CLI)

Script mínimo que muestra el raw output del CLI en cada paso. Sin imports de tests/lib.

python tests/example/test_minimal.py # Muestra: config, .ai/ files, raw stdout, parsed events, resultado final

Por qué: Un script que muestra el raw output resuelve más que 3 sesiones de "arreglar el parsing".

Lecciones Aprendidas

8. returncode 0 no significa exito

El API devolvía error 426 en stdout con returncode 0. Sin ver el raw output, parecía que el modelo respondía vacío.

Regla: returncode 0 solo significa que el proceso no crasheó. Verificar el contenido de stdout.

9. Un script de raw output resuelve más que 3 sesiones de adivinanzas

test_minimal.py (~120 líneas) mostró el error real en 10 segundos. 3 sesiones de "arreglar el parsing" no encontraron nada.

Regla: Antes de diagnosticar, ver los datos crudos. Crear un script mínimo de validación.

10. Hardcoded paths = fragilidad

9 archivos tenían AppData\Local\opencode\opencode-cli.exe hardcoded. Cuando el usuario instaló por npm, el path cambió.

Regla: Buscar en múltiples ubicaciones. Crear un módulo compartido para rutas.

11. Los scripts de debug se vuelven obsoletos

5 scripts de verificación (verificar_formato_cli.py, etc.) nunca se actualizaron al patrón --dir ni al nuevo CLI.

Regla: Mantener los scripts de debug actualizados. Si no se mantienen, son peor que no tenerlos.

Las lecciones 1-7 de Lecciones 5 siguen vigentes

opencode serve + --attach es un callejón sin salida. La desktop app envenena el entorno. Copiar código entre directorios rompe rutas. Windows cp1252 + Unicode = crash. No inventar, verificar. Timeouts insuficientes. Siempre leer antes de afirmar.

Reglas de Oro (Checklist actualizado)

Antes de ejecutar tests

  • Verificar versión del CLI: opencode.cmd --version debe ser >= 1.17.0
  • Verificar que OPENCODE_CLI apunta al binario correcto
  • Verificar que TEST_PROJECT apunta al proyecto correcto
  • Limpiar OPENCODE_SERVER_PASSWORD y OPENCODE_SERVER_USERNAME
  • Usar opencode run --dir en vez de --attach
  • Sanitizar prints con sanitize() en Windows
  • Calcular timeout suficiente para el número de queries

Al diagnosticar problemas

  • Crear un script de raw output primero (test_minimal.py)
  • Ver stdout y stderr COMPLETOS antes de diagnosticar
  • No asumir que returncode 0 = exito
  • No asumir que el parsing está mal sin ver el raw output
  • Verificar con datos reales, no asumir
