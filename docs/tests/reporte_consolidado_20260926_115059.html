## 1. Entender el problema Ordenar una lista de números en Python es una operación estándar. La pregunta clave es: ¿se quiere un **nuevo** objeto ordenado (sin tocar el original) o **modificar** la lista en el sitio? Python ofrece una función y un método para cada caso. ## 2. Proposición de solución ```python # Caso A: genera una nueva lista ordenada (el original no cambia) numeros = [5, 2, 9, 1, 7] ordenados = sorted(numeros) # Caso B: modifica la lista original (más eficiente, sin copia) numeros.sort() # Caso inverso (descendente) descendentes = sorted(numeros, reverse=True) # Ordenar por un criterio derivado de cada elemento from operator import itemgetter usuarios = [("ana", 30), ("luis", 25), ("bob", 41)] por_edad = sorted(usuarios, key=itemgetter(1)) ``` ## 3. Razonamiento - `sorted()` es una **función**: recibe cualquier iterable y devuelve una lista nueva. Más flexible, pero crea una copia en memoria. - `list.sort()` es un **método**: reordena la lista existente y devuelve `None`. Evita la asignación extra y es la opción preferida cuando ya tienes una `list`. - Ambas usan **Timsort** (algoritmo estable, O(n log n) en el caso promedio), por lo que los elementos con la misma clave conservan su orden relativo. Esto importa al ordenar por un campo como `edad` sin que el orden previo se pierda. - `reverse=True` no invierte el algoritmo, solo invierte la comparación final, así que mantiene la estabilidad en orden inverso. ## 4. Mejoras y alternativas - **Claves complejas**: en vez de `itemgetter`, usa `key=lambda x: x["edad"]` o claves múltiples `key=lambda u: (u["edad"], u["nombre"])`. - **Orden natural de strings numéricos**: si los datos vienen como texto (`"10"`, `"9"`), `sorted()` ordenará alfabéticamente.
