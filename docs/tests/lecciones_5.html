Causa Raíz: Por qué fallaba cada enfoque

❌ ANTES: opencode serve + --attach

opencode serve inicia un servidor HTTP que acepta conexiones. Pero no crea sesiones que --attach pueda encontrar.

--attach intenta conectarse a una sesión existente → "Session not found" → stdout vacío.

Analogía: Es como llamar a una oficina que no tiene recepcionista — suena el teléfono pero nadie contesta.

✅ DESPUÉS: opencode run --dir

opencode run --dir test-ai-config crea su propia sesión, procesa el prompt, y devuelve la respuesta directamente por stdout.

Sin server intermedio. Cada query es independiente, como la desktop app.

Analogía: Es como hablar directamente con alguien en vez de llamar a una oficina vacía.

Los Fixes (4 Cambios)

Fix 1: --dir en vez de --attach (model_runner.py)

Eliminamos opencode serve y --attach. Ahora cada query usa opencode run --dir TEST_PROJECT.

# ANTES (broken) cmd = [OPENCODE_CLI, "run", "--attach", f"http://127.0.0.1:{self.server_port}", "--model", self.model_id, "--format", "json", prompt] # DESPUÉS (funciona) cmd = [OPENCODE_CLI, "run", "--model", self.model_id, "--format", "json", "--dir", TEST_PROJECT, prompt]

Por qué: Cada opencode run crea su propia sesión al estilo de la desktop app. Sin dependencia de un server externo.

Fix 2: Limpiar env vars de la desktop app

La desktop app inyecta OPENCODE_SERVER_PASSWORD y OPENCODE_SERVER_USERNAME al entorno. Los procesos hijos los heredan → el CLI se conecta al server de la desktop en vez de crear el suyo.

# ANTES (broken) env = os.environ.copy() # DESPUÉS (funciona) env = os.environ.copy() env["OPENCODE_SERVER_PASSWORD"] = "" env["OPENCODE_SERVER_USERNAME"] = ""

Por qué: Al limpiar las variables, el CLI no detecta un server existente y crea su propia sesión correctamente.

Fix 3: PROJECT_ROOT correcto (model_runner.py)

Al copiar model_runner.py de src/doc/ESTRUCTURA/ (3 niveles) a tests/lib/ (2 niveles), la ruta relativa quedó mal.

# ANTES (broken - 3 niveles, copiado de src/doc/ESTRUCTURA/) PROJECT_ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "..", "..", "..")) # → Apunta a C:\ (raíz del disco) # DESPUÉS (funciona - 2 niveles, tests/lib/) PROJECT_ROOT = os.path.abspath(os.path.join(os.path.dirname(__file__), "..", "..")) # → Apunta a personalizar-comportamiento-01/

Por qué: Siempre verificar PROJECT_ROOT después de mover archivos entre directorios.

Fix 4: sanitize() para Windows (test_ai_structure.py)

Windows usa cp1252 por defecto. Caracteres como é, á, ñ crashean print() con UnicodeEncodeError.

# ANTES (crash en Windows) print(f" Test {r['id']} -> {r['description']}") # → UnicodeEncodeError: 'charmap' codec can't encode characters # DESPUÉS (funciona) def sanitize(text): return text.encode('ascii', 'replace').decode('ascii') print(f" Test {r['id']} -> {sanitize(r['description'])}")

Por qué: encode('ascii', 'replace') reemplaza caracteres no-ASCII por ?, evitando el crash.

Lecciones Aprendidas

1. opencode serve + --attach es un callejón sin salida

--attach busca sesiones en el server, pero opencode serve no crea sesiones que el CLI pueda encontrar. Es un patrón roto.

Regla: Usar siempre opencode run --dir <proyecto> para tests.

2. La desktop app envenena el entorno

Inyecta OPENCODE_SERVER_PASSWORD y OPENCODE_SERVER_USERNAME al process.env. Los procesos hijos los heredan silenciosamente → el CLI se conecta al server de la desktop en vez de crear el suyo.

Regla: Siempre limpiar esas variables antes de subprocess.run().

3. Copiar código entre directorios rompe rutas

model_runner.py vivía en src/doc/ESTRUCTURA/ (3 niveles), se copió a tests/lib/ (2 niveles). os.path.join(__file__, "..", "..", "..") quedó mal.

Regla: Verificar PROJECT_ROOT manualmente después de mover archivos.

4. Windows cp1252 + Unicode = crash silencioso

print() en Windows usa cp1252, no UTF-8. Caracteres como é, á, ñ crashean el script sin aviso claro.

Regla: Usar sanitize() antes de toda impresión a consola.

5. No inventar, verificar

Asumí que el problema era el formato de salida del CLI cuando en realidad era el env var. El usuario me paró: "no vamos a inventar cosas".

Regla: Si una tool falla, re-intentar antes de diagnosticar como "caído". Verificar con datos reales.

6. Timeouts insuficientes

3 modelos × 9 preguntas × ~30s = ~13 min, pero el timeout del tool era 600s (10 min). El test se cortó antes de completar.

Regla: Calcular timeout = (n_modelos × n_preguntas × 30s) + margen.

7. Siempre leer el archivo antes de afirmar

Dije "el formato de salida cambió" sin haber verificado el archivo. El usuario me corrigió: primero lee, después opina.

Regla: Nunca afirmar el contenido de un archivo sin haberlo leído primero.

Reglas de Oro (Checklist)

Antes de ejecutar tests

  • Verificar que TEST_PROJECT apunta al proyecto correcto
  • Verificar que PROJECT_ROOT es válido (imprimir os.path.dirname(__file__))
  • Limpiar OPENCODE_SERVER_PASSWORD y OPENCODE_SERVER_USERNAME
  • Usar opencode run --dir en vez de --attach
  • Sanitizar prints con sanitize() en Windows
  • Calcular timeout suficiente para el número de queries

Al copiar/mover archivos

  • Verificar PROJECT_ROOT después de mover
  • Contar niveles de .. en rutas relativas
  • Probar que el archivo se importa correctamente

Al diagnosticar problemas

  • Leer el archivo antes de afirmar su contenido
  • Re-intentar la tool antes de diagnosticar como "caído"
  • Verificar con datos reales, no asumir
  • "No vamos a inventar cosas" — verificar primero
