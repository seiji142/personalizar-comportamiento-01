## Lecciones aprendidas

1. **Antes de diagnosticar "lentitud", verificar que el sujeto existe:**
   IDs de modelo obsoletos y procesos que mueren al arrancar imitan
   timeouts.
2. **Normalizar ambos lados del matcheo:** si quitas tildes del texto,
   quítalas también del patrón.
3. **stderr a DEVNULL esconde la causa raíz:** fail-fast con exit code +
   tail de stderr convierte 30s de timeout en 1s de error claro.
4. **Un cap que nadie alcanza no necesita subirse:** los datos del run
   instrumentado refutaron las hipótesis de las tareas 6 y 10.
5. **TPD diario ≠ lentitud del modelo:** los retries de 429 inflaban el
   wall histórico de gpt-oss.
